## 1. 总体判断与范围

项目已具备“开发板拍照及传感器采样 → Windows ADB 拉取校验 → 本地云 API 上传和查询”的实板演示闭环，当前处于整机回归、异常恢复和生产集成阶段，尚不能认定为野外无人值守产品。

## 3. 优先困难

1. **自动对焦控制稳定但照片失焦。** 当前真实场景中手动 500 清晰，自动锁焦 280/300 以及连续 AF 280 都明显失焦。两个起始焦距的 30 秒诊断均主动移动并收敛 280，说明单纯延长等待不能解决低纹理场景下的固件 AF 误判。
2. **Windows ADB 不透传板端 shell 退出码。** `adb shell false` 的 Windows 进程退出码仍为 0，只有远端追加 marker 才能看到真实值 1。客户端当前直接采用 `Process.ExitCode`，会漏掉远端 2/10 等协议状态，必须在 Windows Agent 侧封装和解析随机退出码 marker。
3. **软件重启不能恢复。** v5.6.2 实板执行 `adb reboot` 后 UART 报 `Reboot failed -- System halted`，900 秒未恢复，物理 Reset 才恢复。v5.6.3 没有纳入看门狗修复；本次检查 Git overlay 与 SDK 板型配置均仍为 `# CONFIG_WATCHDOG is not set`。本轮按门槛没有执行 `adb reboot`。重启/异常自恢复是无人值守的重要缺口。
4. **当前成品和客户端依赖尚未统一。** v5.6.3 保持 2.17-1；客户端需要 `mosquito-capture`、环境/电源机器接口及 metadata v3，默认优先搜索 `/data/local/tmp/client-demo`。这些属于未提交候选，没有进入当前成品，干净烧录后不能据临时部署记录推断一键客户端直接可用。
5. **GNSS 接收质量仍未查清。** 15×15 天线最多观测 4 颗卫星，既有测试最大 C/N0 约 25–32 dB-Hz，参与定位数量仍为 0。应依既有 GNSS 交接矩阵核对天线/扣接、偏置供电、天空视野及 USB 干扰，不能只按天线尺寸判断根因。
6. **真实生产云和蜂窝业务链缺少实证。** 本地 API 成功不证明 PostgreSQL、OSS 签名上传、ECS 凭据刷新及真实弱网恢复通过；新上传脚本也没有自行建立 PPP，需要把联网、校时、上传和结束流程形成明确业务编排。
7. **可靠性测试范围不足。** v5.6.3 冷启动 3/3 仅证明该项；本轮直连成功路径测试没有替代冷启动 10 次、热插拔、stop/start、4G 共存或生产云集成验收。
8. **时间、电源及安全产品化未完成。** 本轮所有 sidecar 都报告 `system_time_valid=no` 和 1970 时间；可靠关联依赖 UUID、uptime 和 Windows 主机时间。BQ25895 警告 `0x80` 重复出现；当前 ADB 为 root 且关闭认证。低功耗、维护认证和设备身份等仍需形成生产方案。

## 4. 本次额外发现的代码问题

### 4.1 已复现：上传一半后重试可能卡住

`CloudApiClient.UploadArtifactAsync` 对未完成记录会重新上传照片和元数据；本地存储 `LocalObjectStorage.AcceptLocalUploadAsync` 使用 `File.Move(temporaryPath, path, false)`，已经存在的照片会拒绝写入。故“照片已成功，元数据或完成确认失败”后的重试缺少逐对象恢复策略。OSS 路径同样设置禁止覆盖，但本次未进行真实 OSS 测试。

隔离测试对同一签名目标连续上传相同字节，第一次成功，第二次抛出 `IOException`。现有云端测试的幂等项只验证记录创建，未覆盖这一中间失败场景。

### 4.2 已复现：Uploading 状态在重启后不进入重试队列

客户端在网络上传前将 SQLite 记录置为 `Uploading`；异常捕获排除取消，启动初始化也未将中断记录恢复。`OutboxRepository.GetPendingAsync` 只选择 `PendingUpload` 和 `Failed`。

隔离测试先保存待上传记录，待处理数量为 1；置为 `Uploading` 后重新创建并初始化仓库，待处理数量为 0。记录仍保留在数据库，但当前重试入口无法取出它。需要覆盖取消、进程退出及再次启动场景。

### 4.3 源码发现：OSS SHA-256 校验尚未证明对象正文一致

本地存储会计算上传字节的 SHA-256；OSS 路径的 `GetInfoAsync` 则读取 `HeadObject` 返回的自定义 `sha256` 元数据，并与上传声明比较。代码未在该路径重新计算对象正文哈希，不能把本地校验通过外推为生产 OSS 正文已完成同等校验。本次没有真实 OSS 验证。

上述代码均未在本次修改。
