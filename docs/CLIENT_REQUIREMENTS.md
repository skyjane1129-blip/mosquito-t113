## 远程拍照与位置刷新（2026-09-10，客户端已实现）

- 入口：远程右侧“设备信息”卡片，选中设备后显示“对焦值”输入框（与直连共用当前值，默认 500）和“远程拍照”按钮。进行中其他操作禁用，可用底部“取消当前操作”停止客户端等待；取消不撤回云端已下发的指令。
- 流程：`POST /api/v2/devices/{id}/commands`（`{"type":"capture","focus":500}`）→ 每 2 秒 `GET /api/v2/commands/{id}` → 状态依次为“等待板子经 4G 领取指令 / 板子已领取，正在拍照并上传 / 远程拍照完成”，失败与过期分别提示并显示板端错误码。完成后读取该采集详情并显示照片，刷新设备目录，历史记录提示“有新记录”。客户端最长等待 6 分钟；云端指令有效期 10 分钟。
- 设备卡片显示在线 / 离线（服务端按 180 秒心跳窗口判断）与最近心跳时间、心跳读数（温度、湿度、电池电压、充电状态、板端镜像）、上次定位（坐标、定位方式、采样时间、坐标系）。
- 位置刷新：远程模式每 20 秒静默刷新设备目录，只更新在线状态、读数与位置，不清空已显示照片，不重复请求同一张照片；地图标记按最新 GCJ02 位置重绘。板端定位为 Air780EG 单基站 LBS（合宙官方服务），精度为数百米到公里级，不是 GNSS；服务端把 WGS84 转为 GCJ02 后下发。服务端未给出行政区时，客户端用自绘示意多边形做粗略归区，仅用于地图筛选与计数，不用于地址判断。
- 触发来源显示为“远程指令采集（4G）”；照片关联位置显示定位方式。
- 验证：`dev.ps1 UiTest` 模拟指令 Pending → Dispatched → Completed / Failed、照片替换、静默刷新不清图、失败保留上一张照片；真实板子经 4G 的端到端结果记录在 WINDOWS_DEVELOPMENT.md 的 2026-09-10 节。

## 照片命名（2026-09-16，客户端已实现）

- 规则：`<设备编号>_<采集时间 北京时间 yyyyMMdd_HHmmss>.jpg`，例如 `MQ-SH-001_20260916_111850.jpg`；设备编号未分配时用 ADB 序列号。标注图为 `..._蚊卵标注.jpg`。参照智能虫情测报灯、红外相机等同类产品“设备号加时间戳”的惯例：按名字即可排序、定位设备与时刻，不依赖数据库编号。
- 显示位置：记录查询表格最左列“照片名称”；“放大 / 原图”窗口标题为“原图查看 · 照片名称”（标注图为“蚊卵标注图 · 照片名称”）；照片详情文本第一行；“保存照片”默认文件名；CSV 导出第一列。
- 名称由采集时间与设备编号推导，服务端与板端存储路径不变（仍按采集编号存储）。

## 批量导出照片（2026-09-16，客户端已实现）

- 入口：记录查询表格支持多选（Ctrl / Shift，或 Ctrl+A 选当前页），分页栏显示“已选中 N 条”，按钮“导出选中照片”，导出中可“取消导出”。
- 输出：选择目标文件夹后在其下新建 `蚊虫照片_<日期>_<N>张\`，每条记录存原图 `<照片名称>.jpg`，已识别的再存 `<照片名称>_蚊卵标注.jpg`，并附一份这些记录的 CSV（`采集记录_<时间>.csv`）。本机记录直接复制文件，云端记录逐条取详情后下载。
- 容错：单条失败（链接过期、无照片）记入结果提示，其余继续；取消保留已下载文件。进度显示在查询页消息栏。
- 实现：`Core/PhotoExporter.cs`（可测）、`HistoryViewModel.ExportPhotosAsync`、`HistoryView.xaml.cs` 把 DataGrid 多选交给视图模型。核心测试覆盖命名、标注图、失败与取消。

## 蚊卵识别（2026-09-15，客户端已实现）

- 入口：每个照片面板的按钮行（远程“采集影像”页、右侧“最近一次采集”、记录查询详情）新增“识别蚊卵”和“显示标注图 / 显示原图”。识别需要云端登录，模型在服务端运行（见 mosquito-cloud-service/README.md “蚊卵识别”）。
- 流程：点击 → `POST /api/v2/captures/{id}/analysis` → 每 2 秒 `GET /api/v2/captures/{id}/analysis` → Completed 后下载 `annotatedDownloadUrl` 的标注图并自动切到标注图；按钮变为“重新识别”（带 `force=true`）。失败显示服务端错误原因；等待上限 12 分钟。
- 显示：标注图为服务端绘制（绿框 mosquito、橙框 egg、左上角计数），“放大 / 原图”与“保存照片”作用于当前显示的那张（标注图保存时文件名带“-蚊卵标注”）。详情文本新增“蚊卵识别”一行，已识别的记录重新打开时自动加载标注图。
- 直连模式：照片经 Windows 路线上传后同样可识别；未上传成功的本地记录会提示云端无此记录。
- 验证：`dev.ps1 Build`、`Test`、`UiTest` 通过；服务端冒烟测试覆盖识别状态机。真实照片端到端结果记于工作区 STATUS。

## 统一登录与工作区锁定

- 共用一组账号、密码输入框和一个登录按钮，无登录类型选择器。首次打开和退出后输入框为空，分别显示“账号”“密码”；密码掩码显示，支持回车登录。
- 当前保留账号 `admin` 给工程师本地入口，临时密码 `000`；本机校验，不依赖网络，可以操作真实开发板。密码错误保持锁定，不向云端发送工程师凭据。
- 其他账号调用现有 `POST /api/auth/login`，收到有效 `accessToken` 和未来的 `expiresAt` 后才进入云端会话。无真实云端测试账号时，以模拟接口验证客户端流程，真实认证联调仍待完成。
- 输入为空、认证失败或网络异常均不能解锁。未登录时展示“请先登录”，不查询业务记录、不访问开发板、不执行后台业务轮询；界面、命令及子页面同时检查会话权限。
- 登录成功默认直连，顶部显示“工程师模式”或“云端已登录 · 账号”，以及直连 / 远程按钮和“退出登录”。当前模式青绿高亮，保持原视觉风格。
- 工程师可以进入远程工作区查看结构及接入提示，云端设备、采集记录、上传与上报检查仍需云端会话，不注入模拟生产数据或伪造云端令牌。
- 退出后清除密码控件、会话、云端令牌及当前屏幕数据，关闭原图窗口并取消查询；本机 SQLite 和照片保留。旧异步响应不能恢复上次账号的数据。
- 云端 401 或令牌到期恢复锁定，显示过期提示；普通断网保留未过期会话和已查询快照。直连操作进行中暂禁主动退出和模式切换；若云端会话在本机采集中到期，工作区锁定，已开始的本机保存允许完成，旧结果不重新显示。
- 当前工程师凭据仅用于本阶段开发与现场调试，正式客户交付时的凭据管理仍需在发布阶段确定。

## 直连环境与设备检测（客户端已实现）

2026-09-07 项目负责人提出：接入 Type-C 后，客户端自动检查电脑是否满足数据传输要求，并自动检测开发板连接；需要覆盖没有预装 ADB 的新电脑。

- 登录成功进入直连、从远程切回直连时检查一次；Windows USB 变化通知触发防抖检查，并对启动中的板子进行有限重试，60 秒轮询作为补充。未登录不探测。
- 右侧“设备状态”标题旁显示“检测设备”，运行时为“检测中…”，不可重复发起；结果摘要常驻，分项和检查时间在“检测详情”展开并独立滚动。
- USB 发现独立于 ADB：通过 Windows PnP 识别候选设备、读取硬件标识和系统提供的描述信息、检查驱动问题。USB 未完成枚举时只能显示未发现或识别异常，不能凭空读取型号或编号。
- 当前分层检查 ADB 程序可运行性、USB 设备、WinUSB 驱动、ADB 只读握手、采集 / 环境 / 电源命令存在性、镜像声明的 metadata 版本及身份。目标按配置的 ADB 序列号匹配，发现重号不任意选择。
- 状态区分未发现目标、组件缺失、驱动待确认、ADB offline、板端响应异常、已连接但接口未就绪、有待确认项和检测通过。命令存在不等同于一次真实采集已验证；镜像声明与临时接口可能不同，仍须单独联调。
- 自检仅执行 USB 枚举、ADB version / devices、mosquito-version 和 command -v；不触发拍照、传感器采样、上传或修改板端系统。电脑不联网也能在工程师登录后检测。
- 原需求中的本地保存目录权限与空间预检、测试文件传输保留为后续补充；本轮没有把它们标记为已验证。
- USB 报告的产品字符串与序列号可能固定或过期。正式设备编号和真实固件版本需要通信握手核对；当前统一的 MOSQUITO-T113-DEV 不能作为量产每板唯一编号。

## 客户安装交付要求（已确认，安装包待实现）

- 最终客户端必须打包成可在客户 Windows 10/11 电脑上一键安装的安装包。
- 安装程序自动部署经过验证且允许分发的 ADB 主机组件、匹配依赖和客户端运行环境；软件使用应用内路径并按需启动 ADB 后台进程。客户无需手动安装 ADB、开发 SDK 或配置 PATH。
- 安装流程检查 USB 驱动，优先使用 Windows 内置 WinUSB 自动匹配；确需补装时引导安装匹配硬件的签名驱动，并由 Windows 显示必要权限确认。
- 已安装 ADB 的电脑不应被盲目替换全局工具；应用通信组件应可随客户端统一维护。

## 历史记录

- 直连查询本机 SQLite 已保存记录；远程查询云端。
- 首次默认全部设备、今天、全部状态；快捷时间有今天、昨天、近 7 天、自定义。
- 设备编号、日期、状态修改后显式点击查询。日期含结束日，固定按北京时间，不跟随电脑时区。
- 每页 50 条，按采集时间从新到旧。单击行自动加载详情；切换时立即清空旧图，取消旧请求，防止响应乱序串图。
- 详情含照片、设备编号、采集编号、采集/接收时间、时间来源、触发来源、温湿度、电源、照片关联 GNSS 位置及采样时间。缺失信息明确说明。
- “完整 / 部分完成 / 失败”为记录状态；上传失败另标阶段，不能把有照片的上传失败说成拍照失败。
- 支持原图缩放、100% 大小和保存照片；不批量打包照片。
- 导出当前查询的整个完整快照，跨全部分页；CSV 包含北京时间及时间来源。旧 API 达到 500 条时提示不完整并禁用完整导出，用户可缩小范围。
- 两种模式分别保存当前筛选、页码、选择；在工作区与记录页之间导航不会丢失。这里指本次运行内，不承诺重启恢复。
- 自动检查发现变化仅提示“有新记录，刷新查看”，不会替换正在查看的历史照片或自动重排记录。

## 上报检查与提示

- 独立于采集记录；只在远程模式显示，默认近 24 小时。可以按设备、日期和上报状态查询。
- 计划由服务端确认已经生效，周期 60 分钟，以设备计划锚点为准，不假设整点。生效前不追溯漏报。
- 宽限固定 15 分钟。时段 T 之前为未到时间；T 到 T+15 分钟前等待上报；截止后没有收到可用记录为超时未上报。
- 服务端确认完整或部分完成的记录都算收到；仅开始上传不算收到。T+15 分钟前收到为按时，恰好截止或之后收到为延迟补报。
- 迟到记录更新原时段，去重；不能把较晚时段的照片拿来填补旧缺口。计划、时间或关联不可靠时显示待确认。
- 表格展示计划时间、编号、状态、实际接收时间和说明。收到记录的时段可进入关联详情；漏报无照片入口。
- 工作区以黄色行内提示显示选中设备的超时时段。总览按近 24 小时统计有超时的不同设备数量，可进入检查。
- 每 60 秒检查一次；已查询的上报检查页更新原查询范围内的状态，保留可保留的选择。历史记录只提示更新。
- 断网保留已显示数据和检查时间，明确提示暂停；无声音、强制弹窗或推送，不把休眠、漏报等同硬件故障。
